# DCL-832

Сайт **dcl832.click** и веб-приложение (PWA) для диагностики согласованных действий.
Несколько раз в день, в случайный момент, телефон спрашивает: «Что вы сейчас делаете?»
Пользователь отмечает DCL-код (хочу · согласен · можно, вдвоём — 5 знаков), а приложение
показывает уровень свободы (долю действий без нулей), нагрузку, эустресс и дистресс, а также мишени —
где и в каком разряде копятся нули. Внизу лендинга можно скачать обе книги в PDF.


### Как это работает

1. **Расписание.** Окно бодрствования (по умолчанию 08:00–23:00) делится на N равных
   интервалов, в каждом выбирается один случайный момент (от 3 до 20 сигналов в день,
   по умолчанию 6; пауза между ними не меньше 30% интервала).
2. **Сигнал.** Раз в минуту крон находит сигналы, время которых наступило, и отправляет
   push-уведомление. Нажатие открывает экран ответа. На Android в уведомлении есть кнопки
   «Пропустить» и «Не беспокоить 2 ч» (на iPhone веб-уведомления кнопок не поддерживают).
3. **Ответ.** Действие (кнопки категорий или своё название), с кем (один / вдвоём /
   3 и больше) и разряды D, C, (D₂, C₂), L. Для второго участника есть «?» — не знаю (x).
   При «нельзя» (L = 0) обязательно уточнение: закон, правила места или работы, нормы круга
   (`answers.l_kind`: `law` / `rules` / `norms`); сам код при этом не меняется.
   Сигнал ждёт ответа 30 минут: так ответ будет о моменте, а не по памяти.
4. **Хранение.** Ответы сохраняются на телефоне (IndexedDB) и работают без сети.
   Если пользователь дал согласие, они анонимно копируются на сервер: без имени, почты
   и телефона, только случайный номер устройства.
5. **Цифры** — в штуках действий, время действий не учитывается. Считаются все отмеченные
   действия: и ответы на сигналы, и записи вручную.
   - *Уровень свободы* — процент действий без нулей (111 или 11111), например «4 из 6».
   - *Нагрузка* — доля действий с нулями (0–100).
   - *Эустресс / дистресс* — число действий с D=1 и C=1 (начал сам, по желанию и с согласием)
     и всех остальных.
   - *Коды с нулями: разово или регулярно* — сколько раз и в скольких разных днях встречался каждый код
     с нулями; «регулярно» — в двух и более днях. Приложение не делает интерпретаций и не даёт советов:
     выводы — за пользователем или специалистом (частые варианты описаны на сайте).
   - *Три оси* — сколько раз «да» по D, C и L; *где нули* — по видам действий; *когда нули* — утро/день/вечер/ночь; *по дням* — списком.

   В админке и в CSV есть колонка `source` (`ping` / `manual`): для исследования можно
   отдельно смотреть ответы на случайные сигналы — они не зависят от того, что человек
   решил записать сам.

## Cloudflare Workers + D1 простыми словами

- **Worker** — ваш серверный код (`src/worker.js`). Он не работает постоянно на арендованной
  машине: Cloudflare запускает его в ответ на запрос или по расписанию (крон) в ближайшем
  из своих дата-центров. Операционной системы, обновлений, SSH и настройки HTTPS нет.
- **D1** — база SQLite, которой управляет Cloudflare. Бэкапы (Time Travel, 30 дней)
  и консоль SQL есть в панели управления.
- **Статика** — лендинг, приложение и иконки при сборке встраиваются в воркер
  (`scripts/build-static.mjs` → `src/static-files.js`) и отдаются им же с того же домена.

| | Cloudflare Workers + D1 | VPS |
|---|---|---|
| Цена на старте | 0 ₽ (бесплатный тариф) | от нескольких сотен ₽ в месяц |
| Администрирование | нет: ни ОС, ни обновлений, ни сертификатов | обновления, firewall, HTTPS, бэкапы — на вас |
| Как работает код | запускается на каждый запрос или крон, процесса «в фоне» нет | обычный постоянно работающий процесс |
| Ограничения | лимиты бесплатного тарифа (ниже), только JS/Wasm | ограничен только мощностью сервера |
| Масштаб | растёт автоматически | при росте нужен сервер мощнее |
| Привязка | код под Workers; данные — обычный SQLite, легко выгрузить | никакой |

Лимиты бесплатного тарифа, важные здесь: 100 000 запросов в день, 10 мс процессорного
времени на один вызов, D1 — 5 ГБ, 5 млн прочитанных строк и 100 000 записанных строк в день.
Для 100–300 пользователей запас многократный. Если пользователей станет больше 500 или
в логах появятся ошибки превышения CPU, хватит тарифа Workers Paid ($5 в месяц).

## Как запустить в интернете (один раз, ~20 минут)

Нужны: компьютер с [Node.js](https://nodejs.org) 20+ и бесплатный аккаунт Cloudflare.

1. **Домен в Cloudflare.** В [панели Cloudflare](https://dash.cloudflare.com) нажмите
   *Add a domain* → `dcl832.click` → бесплатный план. Cloudflare покажет два NS-сервера:
   пропишите их у регистратора домена вместо текущих. Активация занимает от минут до суток.
2. **Код.**
   ```bash
   git clone <адрес репозитория> dcl832
   ```
   ```bash
   cd dcl832 && npm install
   ```
3. **Вход в Cloudflare** (откроется браузер):
   ```bash
   npx wrangler login
   ```
4. **База.** Команда выведет `database_id` — вставьте его в `wrangler.toml` вместо нулей:
   ```bash
   npx wrangler d1 create dcl832
   ```
   ```bash
   npm run db:migrate:remote
   ```
5. **Первая публикация** (создаёт воркер на адресе `*.workers.dev`):
   ```bash
   npm run deploy
   ```
6. **Ключи push и пароль админки.** Выполняется один раз. Сохраните выведенный пароль.
   ```bash
   npm run secrets:deploy -- --yes
   ```
   Ключи push больше не меняйте: после смены у всех пользователей перестанут приходить
   сигналы, пока они заново не включат уведомления.
7. **Свой домен.** Блок `routes` в `wrangler.toml` подключает `dcl832.click` и `www.dcl832.click`
   (www перенаправляется на основной адрес). Перед публикацией домен в Cloudflare должен быть
   *Active*, а в его DNS не должно быть записей A/AAAA/CNAME для `dcl832.click`, `www` и `*`
   (например, парковки регистратора) — Cloudflare создаст нужные записи сам:
   ```bash
   npm run deploy
   ```
8. **Проверка.** Откройте https://dcl832.click с телефона, установите приложение, включите
   сигналы, в настройках нажмите «Прислать пробный сигнал».

Дальнейшие обновления: `npm run deploy`. Новые миграции базы: `npm run db:migrate:remote`.

## Книги

PDF лежат в Workers KV (привязка `BOOKS`) и отдаются по адресам `/books/potok-lyubvi.pdf`
и `/books/vremya-po-lyubvi.pdf`. В git они не хранятся. Заменить книгу новой версией:

```bash
npx wrangler kv key put potok-lyubvi.pdf --path "Поток любви.pdf" --binding BOOKS --remote
```

Если меняется число страниц или размер файла, поправьте подписи в разделе «Книги» в
`public/index.html`.

## Ролик

Исходники в `video/`: анимация — обычная веб-страница `video/index.html`, где каждый кадр
рассчитывается функцией `render(t)` по времени озвучки. Тайминги слов (`assets/words.json`)
получены распознаванием речи (faster-whisper) из `assets/voice.mp3`. Музыка синтезируется
скриптом `video/music.py` (без чужих сэмплов), микс — `assets/mix.mp3`. Шрифты Inter и
JetBrains Mono — лицензия OFL.

```bash
node video/render.mjs --stills 15.5,48,76.8 --out video/out
```
```bash
node video/render.mjs --video video/out/dcl832.mp4 --audio video/assets/mix.mp3
```

Предпросмотр кадра в браузере: `video/index.html?t=48` (через локальный http-сервер).
Готовые ролики лежат в KV и отдаются по `/media/<имя>` с поддержкой Range-запросов (нужна Safari
для перемотки): `dcl832-1.mp4` — «Третья цифра» (`video/`, только голос; старое имя `dcl832.mp4` тоже работает), `dcl832-2.mp4` — «Пятёрка или троечка»
(`video2/`), `dcl832-3.mp4` — «Спроектируй жизнь» (`video3/`). Обложки — `public/video/poster*.jpg`.
Новый ролик: добавить имя в `MEDIA` в `src/worker.js` и залить файл:

```bash
npx wrangler kv key put media/dcl832-3.mp4 --path dcl832-3.mp4 --binding BOOKS --remote
```

## Связь: переписка, профиль, запись на консультацию

Вкладка **«Связь»** в приложении: техподдержка, идеи «настроить под себя», вопрос специалисту.
Ответы пишутся в админке (вкладка «Сообщения»), пользователю приходит push без текста сообщения.

- **Профиль** — только имя и код входа вида `XXXX-XXXX-XXXX` (сам код не хранится, только SHA-256).
  По коду профиль открывается на другом телефоне; переписка профиля видна на всех его устройствах.
  После 5 неверных кодов — пауза 15 минут.
- **Анонимно** можно писать во все темы. Снимок недели («Приложить мою неделю») и запись на консультацию —
  только из профиля.
- **Запись**: свободные окна = часы приёма (админка → «Запись») минус занятое время в Google-календаре
  администратора и уже сделанные записи; по умолчанию 10:00–19:00 по Москве, 60 минут, на 3 дня вперёд.
  Запись создаёт встречу с Google Meet, ссылка приходит в переписку, за час — напоминание.
- **Админка как приложение**: на телефоне открыть https://dcl832.click/admin/ → «Установить» / «На экран
  „Домой“», затем кнопка «Уведомления» — новые сообщения и записи приходят push-уведомлением.

### Вход администратора через Google и календарь (один раз)

1. https://console.cloud.google.com → создать проект `DCL-832`.
2. «APIs & Services» → «Library» → **Google Calendar API** → Enable.
3. «Google Auth Platform» (раньше «OAuth consent screen»): тип External, название `DCL-832`;
   в «Data access» добавить scopes `openid`, `email`, `.../auth/calendar.events`;
   в «Audience» нажать **Publish app** (иначе доступ к календарю истекает через 7 дней).
4. «Clients» → Create client → Web application → Authorized redirect URI:
   `https://dcl832.click/api/admin/google/callback` → сохранить Client ID и Client secret.
5. Cloudflare → Workers & Pages → dcl832 → Settings → Variables and Secrets → добавить как **Secret**:
   `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` (почта администратора уже лежит в секрете `ADMIN_EMAIL`).
6. Админка → «Войти через Google» → разрешить доступ к календарю. Google покажет предупреждение
   «приложение не проверено» — это наше приложение: «Дополнительно» → «Перейти».

Refresh-токен календаря хранится в D1 зашифрованным (AES-GCM, ключ из `GOOGLE_CLIENT_SECRET`).
Пароль `ADMIN_TOKEN` продолжает работать как запасной вход.

## Анализ данных

**Админка — https://dcl832.click/admin/** (пароль `ADMIN_TOKEN`, можно запомнить на устройстве):
- *Обзор*: устройства, новые и активные, установлено ли как приложение, сигналы, согласие, кто продолжает
  через неделю; графики по дням (новые устройства, доставленные и отвеченные сигналы); платформы.
- *Устройства*: анонимный список (случайный номер, платформа, запуск — приложение или браузер, даты,
  сигналы, ответы на сигналы за 7 дней, записи и уровень свободы — только при согласии).
- *Метод*: средний уровень свободы, нули по разрядам, что нарушено при «нельзя», коды с нулями и у скольких
  устройств они регулярны, частые коды, CSV.
- *Нагрузка*: сигналы за сутки и сбои, очередь, размер базы, лимиты бесплатного тарифа.

Платформу и способ запуска приложение передаёт при каждом открытии (`POST /api/heartbeat`, без
личных данных).

- **https://dcl832.click/admin/** — пароль из шага 6. Сводка: устройства, доля отвеченных
  сигналов, частые коды, нули по видам действий, по партнёрам и по часам. Кнопка выгрузки
  всех ответов в CSV (открывается в Excel или Google Таблицах).
- **SQL-консоль**: Cloudflare → Storage & Databases → D1 → `dcl832` → Console. Например:
  ```sql
  -- самые частые коды по видам действий
  SELECT category, code, COUNT(*) n FROM answers WHERE source = 'ping'
  GROUP BY category, code ORDER BY n DESC LIMIT 30;
  ```
- Колонки таблицы `answers`: `user_id` (случайный), `t` (момент сигнала), `local_date`,
  `local_hour`, `weekday` (1 = пн), `category`, `label` (своё название), `company`
  (`alone`/`pair`/`group`), `partner`, `d1`, `c1`, `d2`, `c2` (`1`/`0`/`x`), `l`, `code`.

## Локальная разработка

```bash
npm run secrets:dev
```
```bash
npm run db:migrate:local
```
```bash
npx wrangler dev --test-scheduled
```

Приложение откроется на http://localhost:8787. Крон вручную: http://localhost:8787/__scheduled.

Проверки:

```bash
npm test
```
```bash
node scripts/e2e-local.mjs
```

`npm test` проверяет шифрование push по тестовому вектору RFC 8291, подпись VAPID и
расписание с учётом часовых поясов. `e2e-local.mjs` при запущенном `wrangler dev` поднимает
поддельный push-сервис и проходит весь путь: регистрация → подписка → крон → расшифровка
сигнала → ответ → админка → удаление данных.

## Известные ограничения

- **iPhone:** сигналы приходят только после установки на экран «Домой» из Safari (iOS 16.4+);
  кнопок в уведомлении нет, ответ всегда через приложение.
- PWA не видит, когда телефон разблокирован, поэтому сигналы случайны внутри окна
  бодрствования. Сигнал ровно в момент разблокировки возможен только в нативном
  Android-приложении.
- Точность расписания — 1 минута (крон раз в минуту). Сигнал, который не удалось отправить
  в течение 10 минут, считается неотправленным.
- Это инструмент самонаблюдения, а не медицинская диагностика. Связь кодов
  с аллостатической нагрузкой — гипотеза модели.
